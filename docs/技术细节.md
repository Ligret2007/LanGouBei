# 技术细节

[README](../README.md) 的补充：想改代码、换词库，或者想接着做「导入」功能时看这里。使用者不需要读这一篇。

## 1. 掌握度算法

三档评价的编码存在 `models/word.dart` 里：`0 不认识 / 1 模糊 / 2 认识`；`Rating.confirm`（确定认识）只在某个词**还没被任何一次评价过**的首次循环里出现，点了直接进已掌握。

每个词的档案 `WordProgress`：

| 代码字段 | 存档键 | 含义 |
| --- | --- | --- |
| `knowCount` / `fuzzyCount` / `unknownCount` | `k` / `f` / `u` | 三档各被选过多少次（照实统计，不受 3 秒规则影响） |
| `recentRatings` | `r` | 最近若干次有效评价，最多留 3 个 |
| `inWrongBook` | `w` | 是否在错题本里 |
| `lastChosenAt` | `t` | 最近一次被选中的时间（毫秒时间戳），用于排复习队列 |

判定规则：

- **已掌握**：`recentRatings` 满三次且全是 `2`（认识）
- **错题本**：选了「不认识」，进 `inWrongBook`；在「反思」里选「认识」会移出
- **未掌握**：其余情况
- **3 秒规则**：`AppState.answer(...)` 收到的 `elapsedMs` 超过 3000 时，写进 `recentRatings` 的值**一律降级为 1（模糊）**，但 `knowCount / fuzzyCount / unknownCount` 仍按用户实际点的按钮记。界面上不做任何提示——这是有意为之，见 README 里的说明。
- **每 5 个词插一张错题**：答满 5 个新词后**实时**从错题本抽一个（不是开队列时预先抽好），`exclude` 用来跳过这一轮已经出现过的词，避免连续重复。

### 知新队列的排法（`lib/word_queue.dart`）

一条队列由两步拼出来，目标是「顺序猜不到」+「各难度均匀露面」：

1. **分桶**：把候选词（没掌握、也不在错题本里的）按 `level` 分进 `easy / normal / hard / extra` 四个桶。桶内先放**没见过的词**（用种子打乱），再放见过的词（按 `lastChosenAt` 升序，最久没复习的在前）。
2. **按占比交错**（`buildBalancedQueue`）：每一步挑「欠账最多」的那一级 —— `理论上该出数 = (已出数 + 1) × 该级词数 ÷ 总数`，减去实际已出数，差值最大的先出。于是**任意前缀**里各难度的比例都贴着它们在词库里的占比（误差 ≤ 1 张），既不会连着来一串同难度，也不会为了让低频词露面而硬塞。并列时优先换一个难度，仍有多个可选才用种子随机挑。

关于伪随机：`pickStudyWords({seed})` 的种子不传就用真随机（每轮「知新」重新洗一次，同一轮内固定），传了就完全可复现 —— 测试靠这个锁行为。种子不落盘。

> 改之前是按字母排的（`abandon` → `ability` → …），既好猜也容易连着几张同难度。切换词库后队列按新词库重建，但进度是按单词 id 存的，所以背过的词仍然是背过的。


## 2. 存档与持久化

只用 `shared_preferences` 存**一个** JSON 字符串，键名 `flutter.langobei.state.v1`：

```jsonc
{
  "progress": { "apple-easy-1": { "k": 3, "f": 1, "u": 0, "r": [2,2,2], "w": false, "t": 1792246982044 } },
  "daily":    { "2026-10-17": { "c": 71, "r": 33 } },   // c = 选择次数，r = 其中正确
  "settings": { "onboarded": true, "bank": "ext", "examYear": 2027, "themeMode": "system", "preset": "default" },
  "streak": 3,
  "lastStudyDay": "2026-10-17"
}
```

- 连续点选时 600ms 防抖写盘（`_saveTimer`），避免每张卡都落一次盘
- 「清空进度」只清 `progress / daily / streak / lastStudyDay`，`settings` 里的外观偏好（`themeMode` / `preset`）保留；`onboarded` 会被重置，下次打开重新走引导
- 倒计时按 **6 月 7 日** 算距离高考的天数

## 3. 词库文件

`assets/words_gaokao.json`（约 551 KB，3540 词），字段如下：

| 字段 | 说明 |
| --- | --- |
| `word` / `phonetic` / `pos` / `meaning` | 单词 / 音标 / 词性 / 释义 |
| `level` | `easy` 1553、`normal` 887、`hard` 574、`extra` 526 |
| `tier` | `core`（easy+normal+hard = 3014，界面上叫「高考：我是菜鸟」）/ `ext`（extra 526，界面上叫「高考：我是大神」） |
| `id` | `单词-分级-序号`，进度就挂在这个 id 上，**换词库时不要改已有 id** |

内置的两个库**不靠改代码拆**：`assets/banks/index.json` 是随包词库清单，一条记录 = 一个可选的库（`id` / `name` / `asset` / `tier` / `wordCount`）。`core` 带 `tier: core` 只留 3014 个，`ext` 不带过滤就拿到 3540 个。加一个随包词库只要：放 JSON 进 `assets/`、在清单里加一条、在 `pubspec.yaml` 的 `assets:` 里登记。

重新生成（脚本读的是纯文本词表，每行「单词 音标 分级 释义」）：

```powershell
python tool\build_vocab.py                # 用脚本里的默认路径
python tool\build_vocab.py D:\我的词表.txt  # 或者自己指定
```

脚本会打印解析数、重复数、分级分布，并把结果写回 `assets/words_gaokao.json`。四级 / 雅思目前只是 `models/word.dart` 里 `kPlannedBanks` 的占位，要真的做，把 JSON 放进 `assets/` 并在清单里加一条即可——`setBank` 现在接受注册表里的任意 id。

## 4. 主题与配色

- **只染醒目位，不染白**：表面色与正文色统一由**中性灰种子**生成（`theme.dart` 里的 `neutralSeed` 与 `kLight* / kDark*` 常量），只有 `primary / secondary` 这类醒目位置换成主题色。所以卡片、页面底色、正文永远是中性色，白色区域保持纯白；`widgets` 里任何新组件都不要直接用 `colorScheme.primary` 去铺大面积背景。
- **主题色四选一**：色值仍用 HSL 描述（`kThemePresets`），默认 `229/100%/55%`（#1A44FF）、深绿 `152/62%/36%`、紫色 `272/70%/52%`，第四格 `id` 为空表示留空不可选。要加自定义取色，直接复用 `seedForPreset` 这条 HSL 通路即可。
- **老数据迁移**：早期版本存过自由 HSL，迁移时按色相找最接近的预设，差距超过 24° 就回落默认，避免升级后突然跳色。
- **分级配色**：`levelColor(level, brightness)` —— easy 绿、normal 黄、hard 橙、extra 红，深浅色各一套。

```jsonc
  "exportedAt": "2026-10-17T22:30:45.123",

    "studied": 12, "mastered": 3, "wrong": 5, "accuracy": 0.46,
    "know": 9, "fuzzy": 2, "unknown": 1,
    "streak": 3, "levelCounts": { "easy": 1553, "normal": 887, "hard": 574, "extra": 526 },
    "themeMode": "system", "themePreset": "default",
    "today": { "date": "2026-10-17", "choices": 71, "correct": 33 }
  },
  "data": {                        // 与本地存档同构，将来「导入」可以直接喂回 AppState
    "progress": { "apple-easy-1": { "k": 3, "f": 1, "u": 0, "r": [2,2,2], "w": false, "t": 1792246982044 } },
    "daily": { "2026-10-17": { "c": 71, "r": 33 } },
    "settings": { "onboarded": true, "bank": "ext", "examYear": 2027, "themeMode": "system", "preset": "default" },
    "streak": 3, "lastStudyDay": "2026-10-17"

```

- `data` 段与写盘用的是**同一份实现**（`AppState` 的存档组装），落盘和导出不会各写一套；做「导入」时把它读回 `AppState` 即可
- 三条导出通路都在 `ExportService`（`export_service.dart`），原生侧是 `MainActivity.kt` 里的 `langobei/export` 通道：`saveToDownloads`（Android 10+ 走 MediaStore，不需要存储权限；老系统没权限时退回应用外部目录并回报实际路径）与 `shareText`（拉起系统分享面板）
- 平台没实现原生通道时返回「当前平台不支持」而不是崩
- 导出不修改任何状态，也不包含词库本身（词库在安装包里）

## 9. 文字清晰度与动效

**为什么在 2K 平板上有些字发虚**：字号最终要乘「屏幕像素比 × 系统字号缩放」，乘完常常不是整数像素。
比如像素比 2.0、系统字号调成 1.15× 时，12sp 实际是 27.6px，字形按小数尺寸栅格化，边缘就糊；
同一页里有的字号正好落在整像素上（清晰）、有的没有（发虚），所以看起来是「部分字体不清晰」。

**怎么处理**（`lib/crisp.dart`）：在 `MaterialApp.builder` 里把字号缩放结果吸附到 `1/像素比` 的整数倍，
保证 `字号 × 像素比` 一定是整数；同时把逻辑尺寸向上取整到整设备像素（少不到 1px，不会裁切）。
系统字号缩放本身保留，无障碍放大照常生效，只是结果对齐到像素网格。
「更多 → 关于」里那行 `屏幕 1600×2560 @2.00 · 字号 1.15×` 就是排查用的：报这串数字即可判断是不是这个原因。

如果个别机型仍然发虚，那是 Impeller 渲染器在该 GPU 上按小数倍采样的问题——
可以在 `AndroidManifest.xml` 的 `<application>` 里加
`<meta-data android:name="io.flutter.embedding.android.EnableImpeller" android:value="false" />` 退回 Skia 对比。

**动效**：所有时长和曲线集中在 `lib/motion.dart`。翻面 640ms（中段最慢）、卡片换内容 560ms、页面切换 700ms；
曲线默认取 iOS 的 timing function（0.25, 0.1, 0.25, 1.0），带一点缓入、收尾极长；切页再用起步更缓、收尾更长的（0.32, 0.02, 0.18, 1.0）。底部四个板块切换时，
新页从一侧淡入滑回、旧页向反侧淡出，四页始终常驻所以不会丢当前卡片状态。

**只做竖屏**：清单里 `screenOrientation="portrait"`，启动时再 `SystemChrome.setPreferredOrientations`。
Android 12L 起系统会忽略大屏上的方向限制，所以 `MaterialApp.builder` 还把内容区限制在 560dp 宽的居中竖栏，
平板横放时只会变成一条竖屏中栏，不会出现横屏布局。

## 10. 高刷新率（120Hz）

Android 默认会把普通 App 的渲染上限压在 60Hz，哪怕屏幕是 120Hz。实测依据：`dumpsys display` 里
`mDisplayModeSpecs` 的 `render: (0.0 60.0)` 就是这个上限，即使把屏幕显示模式改成 120Hz 也不变。

所以 `MainActivity` 启动后会显式请求屏幕峰值刷新率：

- Android 15+（API 35）：`window.decorView.setRequestedFrameRate(峰值)`
- Android 11-14（API 30-34）：找到窗口里的 `SurfaceView`，对其 `Surface` 调
  `Surface.setFrameRate(峰值, FRAME_RATE_COMPATIBILITY_DEFAULT)`
- 60Hz 屏（峰值 < 90）直接返回，不做任何事

生效后 `dumpsys SurfaceFlinger` 里会出现 `(uid, frameRate)={uid, 120.00 Hz}`。
`更多 → 关于` 那行诊断信息带实测帧率，用相邻帧的 `vsyncStart` 间隔算，所以高刷屏上应该看到 ~120；
如果只有 ~60，说明系统拒绝了这个请求（部分厂商 ROM 会强制锁 60）。

另外每个板块外面包了 `RepaintBoundary`：切页时两页各是一层合成缓存，位移交给合成器，
不会每帧重画整棵子树；离屏页面也能被合成器整层剔除。

**模拟器想跑到 120Hz**，需要把 AVD 的 `config.ini` 里 `hw.lcd.vsync` 从 60 改成 120 并**冷启动**
（`-no-snapshot-load`），否则显示模式里只会报 60。实测软件渲染（`hw.gpu.enabled=no`）下也能跑满 120fps。

## 11. 词库模块化

词库不是一个写死的资源文件，而是一层可替换的接口，内置库和用户导入库走同一套实现。

```
WordBankSource（接口：id / meta / load()）
  ├── AssetBankSource     读 assets 里的随包词库，按 meta.tierFilter 过滤
  └── ImportedBankSource  读用户导入、存在 App 私有目录的词库

WordBankRegistry（注册表）
  ├── builtins    来自 assets/banks/index.json
  ├── _imported   来自 BankStorage.readIndex() 的索引
  ├── all / byId / sourceOf(id)
  ├── import(raw, filename)   解析 → 清洗 id → 落盘 → 更新索引
  └── remove(id)              只允许删导入库

BankStorage（接口）
  └── PlatformBankStorage / MemoryBankStorage
      ├── listImported / read / write / delete
      ├── readIndex / writeIndex
      └── pickFile()  ← 拉起系统文件选择器
```

要点：

- **启动只读两个小文件**：资源清单 + 导入索引。原来启动就把 3540 个词全解析一遍，现在只解析当前选中的那一个库（菜鸟 3014 个），词库再多也不会拖慢启动。
- **id 是进度键**：导入时把 id 清洗成 `[a-z0-9_-]`，撞上已有库（含内置 `core` / `ext`）就自动加 `-2` 后缀；单词 id 由 `deriveWordId(word)` 从拼写推导，所以同一个词在不同词库里共享掌握度。
- **解析宽容**：非 JSON、缺 `words`、格式版本比 App 新才硬失败；重复词合并、认不出的分级按 `normal`、坏记录跳过，都进 `warnings` 里在界面上提示。`formatVersion` 是为了以后改字段还能拒绝读新格式。
- **存储不需要权限**：文件放在 `filesDir/banks/`，`_index.json` 存索引。导出走已有的 `langobei/export` 通道写「下载」目录，导入的文件选择器用 `ACTION_OPEN_DOCUMENT`，同样不要 `READ_EXTERNAL_STORAGE`。
- **界面不关心类型**：`更多 → 词库` 直接遍历 `state.availableBanks`，`builtin` 只影响「能不能删」。加在线词库时只要再实现一个 `WordBankSource`。
- **测试**：`test/bank_format_test.dart` 覆盖格式解析，`test/bank_registry_test.dart` 覆盖注册表（含真实加载内置两库、id 冲突改名、索引损坏降级），界面用 `MemoryBankStorage` 注入。

格式文档见 [`docs/词库格式.md`](词库格式.md)。

## 12. iOS 适配

Flutter 层一行没改：词库解析、注册表、队列、掌握度、动效、主题、字号吸附全部共用。差异只有原生侧，`ios/Runner/AppDelegate.swift` 用同样的通道名把 Android 那两个通道重写了一遍。

| Android | iOS |
| --- | --- |
| `saveToDownloads` 写 MediaStore「下载」 | 写沙盒临时目录后弹 `UIDocumentPickerViewController(forExporting:)`，用户存进「文件」App |
| `shareText` 拉 `Intent.ACTION_SEND` | `UIActivityViewController`（iPad 必须给 popover 锚点，否则崩） |
| 词库目录 `filesDir/banks/` | `Application Support/banks/` |
| 选文件 `ACTION_OPEN_DOCUMENT` | `UIDocumentPickerViewController(forOpeningContentTypes:, asCopy: true)`，`asCopy` 直接复制进沙盒，省掉 security-scoped 授权 |
| 竖屏锁在 `AndroidManifest` | `Info.plist` 的 `UISupportedInterfaceOrientations` 只留 Portrait（iPad 额外允许倒置） |
| 120Hz 靠 `setRequestedFrameRate` | 不用管：`CADisableMinimumFrameDurationOnPhone` 打开后 ProMotion 自动跑满 |

几个坑：

- 模板用的是新的 scene 生命周期（`FlutterImplicitEngineDelegate` + `SceneDelegate`），`window` 不再挂在 AppDelegate 上，所以取视图控制器要用 `connectedScenes` 往上找，代码里的 `topViewController()` 就是干这个的。
- 通道注册从 `engineBridge.pluginRegistry.registrar(forPlugin:)` 拿 messenger，不要再走 `window.rootViewController`。
- App Store 不接受带 alpha 通道的图标；图标是从 `图标.jpg` 居中裁方、`LANCZOS` 缩放出 15 个尺寸，全部存成 RGB 无 alpha 的 PNG。
- 无签名 ipa 用 `flutter build ios --release --no-codesign` 再手动压 `Payload/`，`flutter build ipa` 在没有签名配置时会失败。
- 本地（Windows）只能验证 Dart 层：`flutter analyze`、`flutter test` 全绿；Swift 部分要等 CI 的 macOS 任务编译才算数。
